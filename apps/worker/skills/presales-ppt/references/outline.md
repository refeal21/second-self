# Outline stage

Plan the deck as a narrative and a relationship map before writing page detail.

1. Extract confirmed goals, constraints, stakeholders, source findings, and open questions.
2. Define a stable module catalog. Map every module to evidence and to at least one later function or scenario page.
3. Sequence goals, then one architecture or overview page, then mapped function pages, then role/scenario steps. Include both architecture and overview only when the approved request gives each a distinct purpose.
4. For every page, state one key message, its module membership, and its evidence or visible pending-confirmation item.

Prefer relational forms that match the information: layered architecture for boundaries, a map for module relationships, a sequence for handoffs, a comparison for alternatives, or a hierarchy for containment. Equal cards are appropriate only for genuinely peer items.

Reject a draft that adds an unconfirmed commercial system, interface, benefit, metric, or causal relationship. Present an evidence gap as a question for review rather than filling it with a plausible claim.
