## 复核中修复的问题

- 上传图片的空提示词曾被 TypeScript 记录解析器拒绝；现仅上传允许为空，并增加原生/前端往返检查。
- 同一项目并发提交不同配色或替换图片，不再把先前操作的成功误报为新操作成功。
- 尚未保存的配色变更阻止继续生成/上传/视觉批准。
- 固定提示条曾遮挡预览；改为页面内状态区，两个视口均验证无重叠。
- 模板解析排除未实际使用的 Office 默认主题色；缓存共享 XML 和关系，保留有实际引用的样式颜色。嵌入栅格图片中的颜色不在本版结构化提取范围内。
- 并行 Rust 测试的时间戳临时目录曾碰撞，导致两个测试共用 SQLite；改为原子分配独立目录，固定时钟并发回归已通过。没有为这个测试问题改动生产数据库逻辑。

## 使用

退出旧版后，打开 `artifacts/build/full-slide-style-target/release/bundle/macos/Digital Twin Workbench.app`。进入原 PPT 项目，展开“项目配色与模板参考”，选择模板、确认各颜色角色并保存，随后手动重新生成当前页。第一张图批准后配色锁定。新旧应用共享同一个本地项目库，请不要同时编辑同一项目。

备份/迁移须同时包含应用 SQLite 和工作区，因为独立配色版本与生成请求不在旧 pipeline JSON 内。下一阶段仍是：图片置入模板版式，以及可编辑转换的文字清除、分层和视觉一致性验收。
