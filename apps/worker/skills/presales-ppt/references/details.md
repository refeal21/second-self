# Details stage

Turn each approved outline page into concise visible content plus a separate design plan.

- Build the approved slide-content authority first: title, body items, table cells, chart labels and values, and shape text. Give each visible leaf one canonical ID/path and bind it exactly once from the design plan. A layout recipe names those references and relationships, not their quoted wording. For a legacy shape without companion IDs, reference `title` and `body[index]` once and omit any alternate diagram or scene labels.
- For each visible claim, record whether it is directly supported, a modality-preserving synthesis, or a visible open question. Keep sequence claims as sequence claims. Add automatic/real-time/intelligent behavior, integration or connected status, named step states, and quantitative benefit only when the supplied evidence explicitly supports that modality.
- Keep speaker notes separate and non-visible. If approved content is too dense, propose a split or compression draft for review before freezing it; never move overflow into notes or silently shrink, delete, or rewrite it later.
- Match form to relationships. Use layers, flows, timelines, matrices, comparisons, maps, or a dominant scene when they explain the message better than repeated equal cards.
- Keep function pages mapped to the stable module catalog. A page may cover one module, multiple explicitly coordinated modules, or a further page for the same module.
- Describe each scenario as referenced steps: actor, location, trigger, action, system response, outcome, and handoff. Each functional step maps to an approved module and each displayed label references approved visible content rather than duplicating prose. Actor and place staging stays non-visible and illustrative unless its wording is separately approved; it cannot supply a new function or system response.
- A design description controls layout, emphasis, and visual relationships only. It cannot introduce another label, interface, benefit, or semantic claim.

Leave unsupported detail as a visible pending-confirmation item. Approval remains a separate user action after content and design review.
