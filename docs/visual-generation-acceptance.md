# 2026-09-08 原生图片生成修复验收

## 范围与原因

旧桌面适配器把 `visual.generate` 交给独立 Worker，但生产 Worker 没有图片执行器；环境变量不能证明存在可用的生成能力。与此同时，视觉操作依赖页面本地忙碌/错误状态，离开页面会丢失反馈。

修复使用桌面端现有的 Codex App Server 连接：读取能力、创建专用临时只读会话、等待匹配 thread/turn 的原生 `imageGeneration` 图片事件和成功结束事件，再通过 Worker 校验 PNG、Rust 原子提交检查点。不会读取任意模型返回的文件路径，也没有 API Key 或按量 API 回退。

页面显示等待工具、正在生成、校验保存及已用时间；跨路由恢复正在进行或失败的任务。同一页重复点击不会再开模型任务。旧页重新打开、手动替换图片或进入下一页后，不再重放上一版本的错误。退出整个应用不承诺继续生成。

## 实际原生生成证据

在独立合成项目中运行生产桌面适配器、真实 Codex 0.153.4、已打包 Worker 和真实 Rust/SQLite。没有使用客户材料，没有自动批准视觉页。

- 生成至保存用时 185,453 ms，约 3 分 5 秒。这是一次实测，不是速度保证。
- 原生返回 PNG：1672 × 941，1,060,173 字节；符合现有 16:9 容差和最小尺寸要求。1920 × 1080 是请求偏好，并非服务保证。
- 保存为 `draft`；批准后的细化规格和原有两条审批完全不变。
- 重启独立 Rust 存储验收进程后，检查点和图片字节可原样读回。这不是对正在运行的客户应用执行重启。
- 调用方法只有 `initialize`、`initialized`、`account/read`、`modelProvider/capabilities/read`、`thread/start`、`turn/start`。

本机证据目录：`/tmp/second-self-visual-fix.XtAa5V/`。包含 `real-smoke-result.json`、`real-generated.png` 和合成测试脚本；临时文件不上传 GitHub。
