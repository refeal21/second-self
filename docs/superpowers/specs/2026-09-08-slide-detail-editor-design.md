# 逐页细化编辑与大纲修订设计

日期：2026-09-08

状态：用户于 2026-09-08 确认完整书面方案，进入开发；交付验收尚未完成。

## 1. 已确认的目标

将“审核全部页面细化”的整份 JSON 文本框替换为逐页文档式编辑器，与已有大纲编辑器保持一致。支持逐页查看、修改、新增、删除及排序。标题、正文、表格、图表、构图、图片提示词与来源以中文标签展示，JSON 仅作折叠的只读高级信息。

用户已确认的审批规则：

- 修改正文、构图等细节：保存后继续审核细化，不重新生成整份内容。
- 新增、删除或调整页序：生成大纲修订版，保留旧版本与审批记录，由用户明确确认结构变更。
- 未受影响页面按稳定页面 ID 沿用全部细化内容，而非按页码重新匹配。

本次是已有工作流的跨层改造，不更换技术栈、不改变账号或代理配置、不调用收费 API。开发和测试不修改真实客户项目、不自动提交客户审批、不重跑模型生成。现有 19 页内容须能原样加载；客户材料和正文不进入 Git。

## 2. 方案选择与边界

采用“逐页编辑 + 独立的大纲修订确认”。相比仅将 JSON 排版成只读文档，这满足页面管理要求；相比允许细化直接偏离批准大纲，这保留可追溯的审批依据。也不采用退回材料分析并重生成整份大纲、细化的做法，以免丢失已有人工修改。

适用入口为已有 `detail_review` 项目：

- 尚未生成细化时，保留现有生成入口和跨页面任务状态。
- 已有细化草稿时，进入本设计的编辑与审批流程。
- 已批准细化及后续阶段只提供文档式查看，本次不新增批准后撤回、已出图页面结构重排或导出后的版本分支功能。

不是 PowerPoint 画布编辑器；构图使用文字说明和基础对象表单，不增加自由拖拽绘图、富文本排版、在线协作或新的 AI 生成入口。

## 3. 页面布局与内容编辑

沿用工作区“左侧流程/页码—中间文档—右侧状态”布局和现有视觉样式，不额外增加横向大列。左侧增加页面目录，显示页码与标题；选择页面滚动定位到对应卡片，不触发保存、审批或模型调用。

中间每页是一张独立文档卡片，默认展示页码、标题和正文，详细数据分区可折叠。全部页面均可顺序阅读。顶部显示页数及保存状态，固定操作区提供“保存修改”和“批准全部细化”；固定区不得遮住表单末尾。长内容可以纵向滚动，避免文本框与页面多层滚动导致操作按钮不可达。

| 分区 | 展示及编辑规则 |
| --- | --- |
| 页面标题 | 普通多行自适应输入框，不显示内部 ID；修改标题需同步大纲修订确认，避免大纲与最终页面标题冲突 |
| 页面目的 | 展示对应大纲目的；新页必须填写，修改已有页面目的同样属于大纲修订 |
| 最终正文 | 按原始 `body` 数组逐段编辑，可增删段落；不把换行重新拆分成数组，也不自动合并段落 |
| 表格 | 显示真实表头与单元格；支持表格及行列的增删、编辑，删除需确认；字符串数值保持原样 |
| 图表 | 显示类型、分类和系列数据表，支持合法类型与数据编辑；所有系列与分类数量一致，不将空单元格自动转换成 0 |
| 构图与图片提示词 | 用自然语言输入区展示设计说明；基础矩形、椭圆、线条对象用折叠表单编辑坐标、尺寸、颜色和文字，保留既有单位 |
| 来源与依据 | 显示文件标题、页码/定位、已绑定事实与数据；引用只能来自当前材料分析，允许调整有效引用与定位，不伪造来源或事实 |
| 高级信息 | 默认折叠、只读；供排错查看当前页原始结构，不是必经编辑入口 |

中文长标题、长来源路径需换行；表格在自身容器内横向滚动，整个应用不横向溢出。按钮使用可聚焦原生控件，具备中文可访问名称；表单错误定位到页码与具体字段，颜色不是唯一状态提示。

### 3.1 已恢复数据的无损显示

兼容恢复曾将概念构图、表格备注及来源补充追加到 `imageGenerationBrief`，其中包含结构化 JSON。编辑器不能因“不展示 JSON”而删除这些内容。

- 只对已知的恢复分隔标记及有效补充对象做派生展示，识别后的概念构图、表格备注、来源说明以中文属性列表显示。
- 主提示词与兼容补充分区展示。修改主提示词只替换主文本，补充部分按原字节保留，不重新序列化。
- 重复保存不能重复追加补充；其中按旧索引命名的表格或来源备注不能因当前列表变化而被重新关联到另一对象。用户更改相关表格或引用后，补充标记为“来自恢复原稿，需结合当前内容核对”，保留为历史设计背景；后续提示词必须以当前已批准正文、表格和有效来源为真源，补充不得覆盖这些值。
- 兼容补充本次只读。无法识别的部分显示“原始补充资料已保留”，在折叠原文区查看；不得丢弃，也不得执行其中的指令、HTML 或脚本。
- 普通提示词中包含代码、花括号或引号不等于恢复数据，不能用宽泛正则移除。
- 不将概念构图伪装成已完成的可编辑形状；保留现有视觉审核与转换边界。

## 4. 页面增删与排序

新增按钮可在当前页后插入页面，生成新的安全、唯一页面 ID。新页标题、页面目的、正文及提示词由用户填写；表格、图表、基础形状和来源集合初始化为空，不自动调用 AI。必填内容未完成时允许保留在当前编辑草稿中，但不能保存为可审批版本。

删除须显示页码、标题和确认操作；至少保留一页。确认删除仅作用于编辑草稿，保存前可放弃该次编辑；不得删除客户材料或原始恢复文件。结构修订取消或查看历史时，已保存的旧页面内容仍可找回。

排序沿用“上移/下移”按钮，不以拖拽为唯一操作。页码由当前顺序派生，ID 不变。新增、删除、排序、标题或页面目的修改都会被识别为大纲变化；单纯正文、表格、图表、构图和提示词修改不触发大纲修订。

切页保持所有未保存表单值。删除当前页后定位相邻页；新增后聚焦新页标题，排序后焦点仍跟随同一页面 ID。

## 5. 保存、结构确认与整体审批

### A. 普通内容修改

入口：细化草稿且无结构变更。用户编辑 → 字段校验 → 点击“保存修改” → Worker 校验 → Rust 原子提交 → 显示“已保存，待审核”。

只有持久化成功才清除未保存标记。批准只能针对当前已保存且有效的草稿；未保存时按钮禁用并说明原因。保存失败保留全部输入，显示可重试错误，不跳转、不显示成功。

### B. 大纲结构修订

入口：草稿中存在页面增删、页序、标题或页面目的变化。用户保存时保存“待确认的大纲修订 + 对应细化草稿”，不修改当前已批准大纲。

保存后编辑区显示变更摘要：新增页、删除页、原/新页序、修改前后的标题或目的，并提示“需先确认大纲结构变更”。用户仍可继续编辑和保存同一个待确认修订。

“确认结构变更”仅批准已保存的修订，不等于批准全部细化。确认成功后，新大纲版本冻结并成为当前有效大纲；对应细化仍为草稿，用户继续审核后再点击“批准全部细化”。此过程留在 `detail_review` 阶段，以明确子状态表达待确认，不修改全局顺序或跳过原始大纲审批。

“放弃结构修订”需二次确认，说明同时放弃修订草稿中的内容修改；恢复到发起修订前的已保存大纲与细化内容。放弃的修订保留历史快照和取消记录，不被计为批准。

### C. 整体细化批准

前提：无运行中的写操作、无未保存内容、无待确认结构修订、所有页面校验通过。点击后冻结当前细化版本，并进入首个页面的视觉审核；图片生成仍遵循原有逐页确认流程。结构确认和细化批准始终是两个明确操作。

## 6. 状态与恢复

| 状态/触发 | 界面行为 | 持久化与恢复 |
| --- | --- | --- |
| 初次加载 | 显示恢复中，编辑与审批禁用 | 加载检查点后再初始化编辑器，不能用空表单覆盖已有结果 |
| 未生成细化 | 显示生成入口或真实运行状态 | 沿用已有跨路由任务注册表，不能因切页重复生成 |
| 已保存草稿 | 显示页数、已保存及待审核 | 退出页面或应用后从检查点恢复全部内容 |
| 未保存修改 | 明确提示；允许切页，禁止批准 | 离开项目、切换导航或关闭窗口使用未保存确认；不声称已自动保存 |
| 正在保存/确认 | 操作显示进行中，重复提交禁用 | 操作状态在应用层按项目保存；离开再回来不能重复发送 |
| 待确认结构 | 显示修订摘要，整体批准禁用 | 冷启动恢复相同修订、细化和待确认状态 |
| 保存/确认失败 | 保留草稿及摘要，显示原因 | 不清空，不伪造任务或审批；允许按原操作重试 |
| 版本冲突 | 提示其他操作已更新项目，阻止覆盖 | 原草稿保留；用户明确放弃并载入最新前不自动覆盖 |
| 已批准细化 | 文档只读，不能增删改 | 后续阶段引用冻结版本，不能通过历史编辑器修改 |

未经保存的进程内草稿不承诺在强制退出或崩溃后恢复；正常离开前有明确提醒。已提交成功但响应丢失时，先重载检查点核实结果，不能盲目再提交一次。

后台任务或集合刷新不能重置正在编辑的脏草稿；编辑器按项目 ID、编辑基线和持久化内容同步，不仅依赖可能保持不变的版本 ID。收到较新检查点时，如果存在未保存编辑，则保留输入并进入版本冲突提示。

审批中心和首页以持久化数据派生待办：有结构修订时只展示“确认大纲结构变更”；确认后才展示“全部页面细化待审核”。点击待办进入同一项目编辑器，不建立绕开版本校验的快捷批准路径。历史审批与待办分开展示，不因旧审批仍存在而误显示当前已批准。

## 7. 数据契约与版本策略

### 7.1 向后兼容

保留现有 v1 检查点的严格读取与校验。只读打开旧项目不写库、不迁移文件。新版本引入明确的 v2 检查点契约用于大纲修订；首次结构保存通过一次 CAS 提交升级该项目，原 v1 检查点和产物仍保留。旧版应用不能将 v2 当 v1 读取或写回，须明确提示使用新版。

新增概念及职责：

- 当前 `outline`：当前已批准且有效的大纲；原始草稿阶段行为不变。
- 当前 `slideSpecs`：与当前大纲逐页对应的细化版本。
- `outlineRevisionDraft`：待确认修订，包含修订 ID、基础大纲版本 ID、草稿大纲、同序细化草稿和创建/更新时间；同一项目最多一个。
- `revisionHistory`：已确认或已取消的结构修订以及变更前大纲/细化的不可变快照，用于追溯和恢复原文；取消记录不是审批记录。
- 现有 `approvals`：保留全部历史批准证据；新的结构确认以 `outline_review` 审批类型绑定新的大纲版本，细化批准仍绑定具体细化版本。

所有版本使用唯一 ID、递增 sequence 和独立版本产物路径；不再假定大纲或细化永远是 v1。待确认修订的反复保存可以更新该草稿，但不得覆盖任何冻结版本或历史快照。同一个已取消修订的 ID 不再用于后续新修订。

### 7.2 动作边界

通过现有 TypeScript Adapter → Tauri/Rust → Worker 的边界增加三种明确动作：保存大纲修订、确认大纲修订、放弃大纲修订。参数包含目标修订 ID、基础版本和 UI 所见检查点 revision；不能在保存时偷偷使用刚重载的最新 revision 掩盖陈旧编辑。

普通细化保存也必须携带编辑基线 revision。需要修改引用时，Worker 校验引用属于当前已分析材料。保留原分析、材料、偏好快照和冻结大纲，不能以刷新分析来修复编辑校验。

确认修订必须在同一次持久化提交中：

1. 校验目标修订、基础大纲版本、来源和页面序列。
2. 将当前大纲及细化保留为历史快照。
3. 冻结新大纲、追加新的批准证据，并建立对应的新细化草稿版本。
4. 清除待确认修订，保存新检查点。

写入失败时保持旧检查点完整，不能只更新审批或只更新页面内容。每个成功动作仅推进一次检查点 revision；沿用 Rust 的 CAS、路径保护、原子工作区写入与数据库事务，不绕过原生产路径。

### 7.3 不变量

- 当前细化的页面 ID 和顺序必须严格对应当前批准大纲；待确认细化则严格对应其修订草稿。
- 所有历史冻结版本须有匹配的批准证据；取消或未确认修订不得生成批准证据。
- 待确认修订只能存在于细化尚未批准、没有视觉/导出产物的 `detail_review`。
- 未确认结构修订或未批准细化不能生成图片、转换或导出。
- 旧页面通过稳定 ID 原样合并，不根据数组索引重建，不重排正文、来源或嵌套对象。
- 扩展既有版本、任务顺序、审批来源及检查点形状校验以覆盖新动作；不得简单删除现有校验来让增删通过。
- 重放恢复必须保留真实版本 ID、序号、时间及审批；不能为历史记录重新生成 v1 版本或虚构审批时间。

## 8. 代码影响范围

| 层 | 目标职责与涉及位置 |
| --- | --- |
| 前端编辑 | 新增独立的细化编辑器与草稿转换/校验模块；`native-workspace.tsx` 接入受控草稿、修订摘要和只读查看；复用 `outline-editor.tsx` 的文档式样式与交互规则 |
| 前端状态 | `desktop-adapter.ts` 增加带编辑基线的保存/确认/取消接口；App 未保存保护纳入细化与结构修订；运行操作不得只放在路由组件中 |
| 审批列表 | `collection-read-model.ts` 及相关 UI 派生结构修订待办、更新后的细化待办及历史展示 |
| Worker | `native-pipeline.ts` 及 `ppt-project.ts` 扩展版本、动作、校验与恢复；相关逻辑独立成模块，避免将全部新逻辑继续堆进大文件 |
| Rust | `workbench.rs`、`database.rs` 及生产适配测试核对新版本产物、历史审批和检查点事务；保留现有工作区权限边界 |
| 导出与提示词 | 读取当前有效、冻结的大纲/细化版本；不再依赖固定 v1，原转换与 QA 规则不变 |

本文是该功能的交互与设计依据，不表示现有实现已具备这些能力。现有架构中的全局阶段顺序仍然成立；大纲修订是细化阶段内新增的显式确认子流程。

## 9. 验收标准

- 原有 19 页等价合成夹具可以在文档式界面逐页查看，默认审核入口无 JSON 大文本框。
- 未编辑的正文数组、特殊字符、中文换行、表格字符串和兼容补充内容在加载、保存和恢复后严格相等。
- 修改主提示词不丢失原始构图与来源补充；未知补充保持可查看、不可执行、无损保留。
- 新增、删除、排序、标题/目的修改会创建结构修订；普通正文修改不会创建大纲修订。
- 结构保存不改变旧冻结大纲、不新增审批；确认结构只批准新大纲，不顺便批准细化。
- 确认后页面 ID、顺序、数据与新大纲完全一致；再次新增修订有递增版本，不覆盖前次记录。
- 放弃修订可恢复发起前内容；未受影响页面不重新生成；禁止删除最后一页。
- 保存并退出后，重开页面/应用能够恢复相同草稿、修订和审批待办；处理中离开再回来不会重复执行。
- 未保存修改不能直接批准；普通导航和关闭窗口有提醒；并发陈旧保存不覆盖较新结果。
- Worker 重启、写入失败、响应丢失、版本冲突和错误输入均有模拟集成测试，失败不造成半份修订或半份审批。
- 审批中心进入正确项目的结构确认/细化编辑界面；历史批准不会冒充当前待办。
- 无修订的旧 v1 项目仍可恢复、审批和导出；修订后的项目可完成既有视觉审批、PPTX 转换和 QA 测试流程。
- 前端组件测试、Worker 状态/校验测试、Rust 生产适配测试以及宽/窄窗口浏览器验证通过；打包新版 `.app` 后再交付使用步骤。
