# PPT 输出模板与正文图片套版设计

日期：2026-09-08

状态：用户已确认“保留模板、可编辑标题、正文图片、套版预览审核”的方向。本文为待确认的书面设计，尚未实施；不代表当前应用已支持模板导出。

## 1. 目标、范围与依据

为 Second Self 本地 macOS 工作台增加项目级 PPTX 输出模板。用户选择模板，确认版式与图片位置，审核套入模板后的整页效果，导出保留原模板结构的图片版 PPTX。无需复制图片到 PowerPoint，无需填写 API Key，也不增加付费 API 回退。

目标用户为本人，单机单项目操作。沿用现有 Tauri 2、React/TypeScript、Rust/SQLite、TypeScript Worker 和 Codex App Server。涉及项目设置、逐页细化、视觉审核、审批中心、导出与恢复，不重做全站 UI，不建设模板商城、团队模板库或云同步。

已检查用户提供的“北投ppt模板.pptx”：

- 文件包含 5 张示例幻灯片，尺寸为 12192000 × 6858000 EMU，即 16:9。
- 第 1 页为封面，第 2 页为目录，第 3、4 页使用同一个正文版式，第 5 页为结束页。
- 正文页有独立标题对象、红色标题栏、正文底色及页脚；“正文区：放置生成的图片”是示例文本框，不是真实图片占位符，也没有定义正文区域的完整边界。
- 模板包含 2 个母版、31 个版式。封面、目录、结束页的部分元素来自版式层，不能仅复制当前幻灯片 XML 后忽略关系文件。
- 目录示例为 5 行。示例内容不是新项目的事实来源。
- 首次本机 LibreOffice 预览出现部分中文缺字，另一导入预览可显示相应文字。这是渲染兼容风险，不足以断言模板损坏；验收必须检查真实字体与实际输出。

原始 PPTX、品牌图片、预览和客户正文仅在本机使用，不加入公开 Git 仓库。现有可编辑导出及其已记录的长正文遮挡问题不在本次修复范围内，不因模板功能开发而宣称已解决。

## 2. 采用的方案与交付边界

采用“复用模板结构、正文区填图、模板标题保持可编辑”的方案。图片保留为一个可移动、可替换的图片对象；图片内部的正文、表格、图表不承诺逐项编辑。

对比过的方案：

- 将现有整页 PNG 等比缩小放入正文区：可以复用旧图片，但字体会随之缩小，且可能与模板标题重复。允许用户主动上传并审核此类图片，不自动裁掉标题、不将其描述为内容区原生生成。
- 按模板正文区域生成图片：作为默认方式，图片不包含模板页标题、Logo、页脚或外框，适合保持模板的品牌元素与阅读空间。
- 将全部内容重建为可编辑对象并套版：涉及另一套排版、字体与对象匹配保证，不纳入此次图片套版实施范围。

提供两种明确命名的制作模式：“可编辑版（现有流程）”与“模板图片版”。上传模板后，用户通过“确认模板并使用模板图片版”显式选择后者。未使用模板的项目保持现状，不能将图片版误标为可编辑版。

第一版每个项目同一轮制作只激活一种模式。第一次视觉任务开始前可以切换；已有视觉版本、导出或 QA 的项目不原地切换模式。不会把内容区图片直接送入旧的整页遮罩导出器，也不要求模板图片版先完成一次无关的可编辑转换。两种模式共用批准后的大纲和细化，但各自使用适用的视觉与 QA 契约。

“保留可编辑版”指原功能继续供选择该模式的项目使用，不表示模板图片版项目同一轮自动交付两份不同保证的文件。第一版如需两种交付，应分别建立对应模式的项目；不新增项目复制或同项目多输出分支功能。此限制属于本次书面确认的范围。

## 3. 模板入口与可用阶段

在 PPT 项目的“项目说明与提示词”附近增加“输出模板”区域，和“内容材料”明确分开；新建项目后与已有项目使用同一个入口。

主流程：选择本地 PPTX → 安全导入副本 → 本地解析并生成模板缩略图 → 确认封面、目录、正文、结束页的原型及可替换区域 → 保存模板配置 → 按批准后的页面配置套版。

输入与状态规则：

- 第一版接收未加密的 `.pptx`，同时验证实际 ZIP/OOXML 内容，不能只检查扩展名。`.ppt`、`.pptm`、PDF、图片不作为输出模板。
- 上传、解析、预览分别显示进度。选择文件不等于模板已经可用，成功保存后才显示“模板已保存”。
- 可在 `intake`、`source_analysis`、`outline_review`、`detail_review` 以及尚无视觉任务或版本的 `visual_review` 设置模板；正在生成、提交、审批或存在未保存编辑时禁止并发修改，先完成或保存当前操作。
- 用户现有细化项目可以直接添加模板，不要求重跑材料分析、大纲或细化；待确认的大纲结构修订先处理完，再确认页面映射。
- 第一次视觉任务开始后，模板、模式、字体策略、区域和映射冻结。此版不增加批准后换模板、自动批量重生成或跨模式迁移；界面说明需在出图前调整，或另建项目使用新模板。
- 冻结前先检查所有已映射页面的字体、文字容纳和渲染能力。检查失败不开始图片生成、不冻结配置；取消或失败的预检查不算“第一次视觉任务”。字体检查通过不代替后续逐页审核。
- 冻结前替换模板先解析新副本，成功后用户再确认切换；失败时保留当前可用模板。移除需确认，只解除当前选择，保留历史副本及配置记录，不删除用户原文件。
- 无模板仍可使用原有可编辑流程。模板识别失败不自动切换成“仿模板”导出，也不让用户编辑 JSON。

模板保存在项目工作区 `visuals/template-assets/<assetId>/template.pptx`，不进入 `sources` 或材料分析清单。沿用现有六个顶层产物目录，不为了模板扩大任意工作区写权限。项目保存后不再依赖原文件的绝对位置。

## 4. 页面角色、页数与可替换区域

### 4.1 页数真源

最终 PPT 的页数、页面 ID、顺序和标题来自批准后的大纲与细化，不能因模板有 5 页就只输出 5 页，也不能自动追加封面、目录、结束页形成 N+3 页。

这里的页面 ID 是工作台业务 ID，不是 PowerPoint 内部 slideId、部件名或关系 ID。导出时生成有序清单，绑定每个业务 ID、输出位置、实际 PPTX 页面部件路径、候选版本与内容哈希，并纳入 receipt 哈希证据。QA 解析 PPTX 的实际页面顺序与资源，逐项核对清单；允许安全重新分配内部 ID，不能据此改变业务页面对应关系。

模板的封面、目录、正文、结束页是可复用的“页面原型”。使用哪个原型由显式页面映射决定，不通过中文标题猜测后直接执行。用户查看缩略图和页码确认映射；未指定特殊角色的页面默认使用正文原型。模板第 3、4 页相同，可默认推荐第 3 页作为正文原型。

新项目在大纲审批前展示建议角色与总页数，用户可在大纲编辑器中增删页面。已有批准大纲保持原样；细化仍为草稿时，如果用户需要增加封面、目录或结束页，沿用已有大纲修订确认流程，不能由模板导出器偷偷补页。细化已冻结则不开放结构修改，只能选用能容纳现有内容的原型；不能为套模板自动解冻细化。

### 4.2 原型填充规则

| 原型 | 替换内容与校验 |
| --- | --- |
| 正文 | 批准标题填入明确绑定的标题对象；批准正文、表格、图表和构图作为内容区图片的生成依据；示例说明文字仅在指定对象上移除 |
| 封面 | 用批准标题替换封面标题，保留原有品牌元素；如果本页还有正文等内容而模板没有绑定的容纳区域，阻止确认并提示改用正文原型或修改细化，不得丢弃内容 |
| 目录 | 使用该页已批准正文条目逐行填充目录对象，标题单独绑定；不保留模板示例条目，不擅自概括正文或重新编造章节；无需 ImageGen 的目录仍要审核整页预览 |
| 结束页 | 保留已确认的品牌和结束语，批准标题填入绑定对象；存在其他批准内容时同样必须有容纳区域，否则阻止该映射 |

目录示例只有 5 个条目位置：条目不足时清空未用的示例文字及对应编号；超过容量时显示“当前目录版式最多容纳 5 项”，允许改用正文原型，或在细化仍为草稿时通过既有修订增加目录页，不截断、不自动缩成极小字体、不自动增页。新增页仍计入总页数并履行原有审批。

一条目录严格对应一个顶层 `body[]` 字符串，条目数量即该数组长度。每条须非空、不含换行且能容纳于绑定区域；含多段正文、空条目或过长文本时阻止目录映射。应用不自动拆分、合并、去空白或改写字符串，用户在细化草稿中修改后按原流程审批。

页面角色只决定呈现，不得覆盖批准文案。无法完整容纳正文、表格或图表的封面/目录/结束页映射必须报错，不能把相关字段静默忽略。新生成内容不得引用模板示例作为材料依据。

### 4.3 区域配置

模板设置以缩略图展示标题区域、正文图片区域和保护区域（标题栏、Logo、页脚）。正文区域由解析结果推荐，但必须由用户确认；不把“正文区”提示文本框的小尺寸当成完整图片区。

支持选择目标标题对象、选择正文原型，以及通过图上矩形和对应的数值输入调整正文区。矩形拖动不是唯一操作方式，键盘可操作数值输入。边界按模板实际尺寸转换，存储为确定的 EMU 坐标，不硬编码所有模板为 16:9。

图片默认 `contain`：等比缩放、完整显示、居中，禁止拉伸和自动裁切。透明区域透出模板原底色。内容区必须完全在画布内，不得与保护区域相交；调整后立即更新预览并重新校验。

动态字段若来自共享版式，则复制该版式生成本项目私有实例，再替换绑定对象，避免改动其他页面。不全局替换所有“标题”或所有文本框，不改写母版中无关元素。

## 5. 图片生成、整页预览与审批

模板导入、检查点升级、原型和区域草稿可在 `detail_review` 完成。此时“确认模板并使用模板图片版”只选择模式与模板资产，不产生最终页面绑定或视觉审批；页面映射显示“草稿，细化批准后确认”。

完整绑定的“确认本次套版配置”仅在细化已冻结、尚未开始视觉任务的 `visual_review` 开放，绑定准确的批准大纲、细化版本及页面 ID。细化编辑或结构修订后，旧映射草稿显示“需重新核对”，保留仍有效的 ID 绑定，不按新页码错误迁移。细化批准本身不自动确认模板绑定。

模板模式的正文图提示词增加渲染上下文：正文区比例、允许区域、背景策略、最终文字与数据、来源、与模板协调的配色，以及“不重复页标题、Logo、页脚”的要求。这个上下文单独版本化，不改写被冻结的 `imageGenerationBrief` 或批准文本。

提示词不能保证模型一定遵守。整页预览必须展示实际生成图片，重复标题、缺字或遗漏内容时由用户退回修改/重新生成；不能用 OCR 结果反向覆盖批准文本。用户也可以上传替换 PNG，看到等比放置后的真实效果再批准。

每页的执行链为：生成/上传正文 PNG → 校验并保存候选 → 使用同一模板组合逻辑生成单页候选 PPTX → 本地渲染整页预览 → 等待本页审批。封面、目录或结束页若只需填模板文字，则本地组合预览，不伪造 ImageGen 调用或生成记录。

审核默认显示完整模板页面，可展开查看正文原图。右侧区分“正在生成正文图”“正在套版”“正在生成预览”“等待审批”“失败，可重试”，不能仅用禁用按钮代表后台状态。

批准绑定整个候选组合：批准细化版本、页面 ID、模板文件哈希、映射配置哈希、字体策略、正文图哈希（如有）、单页候选 PPTX 哈希和整页预览哈希。导出不得重新生成、另换图片或换布局后沿用旧审批。

当前页批准后才进入下一页；模板不含图片的页面也不自动跳过审批。重新打开某一页仅新增该页视觉候选，保留其他页有效审批和所有历史记录，清除本轮模板导出/QA 的有效指针。不能删除旧交付文件。

## 6. 导出与质量检查

### 6.1 独立导出器

增加 `TemplateImagePptxExporter`，与现有 `PptxGenJsExporter` 隔离。模板版通过 PPTX 包级复制与有命名空间的 XML 编辑复用母版、版式、主题、媒体和相关关系；不将整个模板栅格化成一张背景图，不依赖重新绘制 Logo。

导出输入只接受有效配置和已批准的候选组合。按页面映射复制原型、重映射关系及部件 ID，填入标题和正文图片，保留所需的主题与版式继承。复制页的备注关系必须独立；备注中的来源来自当前批准规格，不把模板旧项目备注作为新项目依据。外部链接不自动访问。

单页候选和最终整份 PPTX 必须复用同一组合实现。最终输出逐页复核对象与图片绑定，并与已批准预览比对，不允许“预览一套布局、导出另一套布局”。

每次导出使用新版本路径，例如 `exports/template-image-<receiptId>.pptx`，文件名可展示为“项目名称-模板图片版”。原有可编辑交付文件及证据不覆盖。

### 6.2 独立 QA

模板图片版使用单独的导出和 QA 记录，不冒用原有 `exportReceipt` 或原可编辑对象检查结论。`templateExportReceipts[]`、`templateQaReports[]` 保存不可变历史，`currentTemplateExportReceiptId`、`currentTemplateQaReportId` 指向本轮结果。文中的 `templateExportReceipt`/`templateQaReport` 指由这些 ID 解析出的当前记录，不是反复覆盖同一历史对象。

必须验证：

- 输出页数与批准页数一致，页面 ID 与顺序一致，每页引用正确的候选、模板及规格版本。
- 标题仍是独立可编辑文本，文本与批准标题逐字一致；正文图片字节哈希与批准候选一致。
- 原模板 Logo、背景媒体、所需母版和版式保持来源可追溯；所有内部关系可解析，无丢图、重复 ID 冲突或悬空资源。
- 正文图片未拉伸、未裁切、未越界，标题栏和页脚保护区未被图片覆盖；标题和目录文字不溢出。
- 本地渲染全部 N 页，逐页比较最终渲染与已批准的完整套版预览，不能拿整页结果和正文小图比较。
- 字体检查覆盖模板动态文字及可见固定文字；缺字、替换导致错位、白页或缺失资源时阻止“QA 通过”。不能仅凭低像素差给出通过结论。

保持现有可编辑版 QA 独立运行，不要求图片版的正文/图表成为可编辑对象。两种模式的验收结果不能互相代替。模板版通过其自身 QA 后即可达到 `completed`，不依赖可编辑版完成。

字体策略默认保留模板字体。冻结前检测到缺失时明确显示所需字体；用户可自行安装后重试。对绑定的动态标题/目录文字，也可显式选择本机替代字体并审核全页预览；固定品牌文字的缺失字体则提示安装，不全局替换母版字体。应用不下载字体、不改系统字体、不静默替换。记录预览使用的实际字体与渲染环境标识；冻结后若环境发生变化导致不能复现，提示恢复原字体/渲染环境后重试，不能中途换字体或换配置后复用审批。本版不提供冻结后全套换字体的批量重新审批流程。

QA 重试保留每轮报告。最多两轮自动技术修复，仅可修复关系或打包等不改变批准内容与布局的错误。需要改图时重新打开对应页、生成新候选并人工审批；需要改字或改模板配置时明确阻止自动修复，遵守本版内容与配置冻结边界，不能以 QA 重试为由解冻或自动批准。

技术修复产生新 PPTX 时新增 receipt，随后 QA 绑定新 receipt；同一 PPTX 重试渲染则新增报告并引用原 receipt。新导出和重新打开页面均清除当前 QA 指针，失败报告可以成为当前报告但不能作为通过证明；旧 receipt、报告及其文件始终保留。

## 7. 数据、状态机与进程边界

### 7.1 分层职责

- React：模板入口、字段与区域配置、页面映射、整页审核、错误和恢复提示。只通过 Adapter/Tauri 访问数据，不直接读写文件或 SQLite。
- Rust：文件选择授权、真实路径与符号链接校验、安全复制、哈希核实、持久化 CAS、任务监管和渲染进程监管。
- Worker：受限模板解析、区域/映射校验、模板组合、视觉证据、独立导出与 QA。新逻辑拆到模板专用模块，不集中追加到已有大文件。
- Codex：本功能新增的模型调用仅用于用户发起的正文图生成；模板导入、复制和版式解析均为本地操作，不为模板分析创建额外模型任务。原有材料分析、大纲与细化的模型流程保持原职责。

使用现有工作流顺序 `intake → source_analysis → outline_review → detail_review → visual_review → conversion → qa → completed`。模板解析和配置是项目内子状态，不代替材料、大纲、细化或视觉审批。

### 7.2 主要记录

- `TemplateAsset`：ID、原文件名、媒体类型、副本相对路径、SHA-256、字节数、导入时间。原文件路径不进入生成提示词或 Git。
- `TemplateInspection`：绑定资产哈希的实际尺寸、原型、对象定位、版式/母版关系、字体、保护区域和明确的兼容问题。
- `TemplateBinding`：配置版本、选定原型、标题目标、正文区域、目录目标及容量、字体策略、页面 ID 映射、规格版本、确定性配置哈希和确认记录。
- `TemplateVisualVersion`：每页候选版本，正文图（可空）、单页 PPTX 和完整预览的路径/哈希/大小，配置与规格版本、审批状态。
- `TemplateExportReceipt`：交付文件路径/哈希/大小，规格版本、模板/配置哈希、所有页面候选版本与预览哈希、导出器版本。
- `TemplateQaReport`：绑定 receipt 的逐页结构、内容绑定、字体、渲染和比对结果，轮次、工具版本、错误及人工验证状态。

大文件仍存项目目录，SQLite 保存索引与轻量状态。模板原文件、历史配置、已批准候选和交付产物采用不可变版本路径；“当前可用”的指针与历史分开。

### 7.3 向后兼容与有效性

采用明确的 v3 检查点，不向 v1/v2 严格结构偷偷插入字段。首次保存模板时，在一次 CAS 提交中升级此项目；仅打开旧项目不写库、不迁移。无模板的 v1/v2 项目继续使用原有严格校验和原流程。

v3 保存一次不可变的迁移起点（原样、已校验的 v1 或 v2 检查点）及升级后的有序动作记录。起点不能包含 v3；原 v2 内合法的 v1 修订起点原样保留，禁止任意递归嵌套。迁移不得重编号历史版本、伪造时间或重新生成审批。

v3 的模板专用验证器核对当前状态与动作重放结果，并继续执行内容、大纲修订、来源和审批不变量。所有新动作使用显式、闭合的数据契约；不能通过删除原有精确字段校验接受任意模板对象。

模板模式下使用独立候选、导出和 QA 字段。普通模式保持原字段的语义，不能将完整套版预览伪装成旧流程的正文背景，或利用旧 `completed` 状态绕过模板 QA。工作流的阶段推进按当前冻结模式选择证明条件。

保存、配置确认、候选提交、视觉批准、导出与 QA 均携带 UI 所见 `expectedRevision` 和唯一操作 ID。Rust 检查历史前缀不可改、产物哈希匹配、模式/配置冻结条件与证据完整性；提交响应丢失时按操作 ID 和已落盘结果核对，不能盲目重发任务。

## 8. 跨页、失败与恢复交互

| 状态或事件 | 显示与操作 | 恢复规则 |
| --- | --- | --- |
| 无模板 | 显示选择模板及模式说明 | 不影响原流程 |
| 正在导入/解析/渲染 | 显示阶段及取消/等待状态；禁止重复提交 | 操作登记在应用层及持久化任务记录中，离开页面不丢失 |
| 导入失败 | 中文错误，保留原有有效模板 | 允许重新选择或重试，不自动读其他文件 |
| 配置未保存 | 显示“有未保存修改” | 切模板页保持草稿；离开项目或关闭窗口提醒；不承诺强退后恢复未保存内容 |
| 配置已保存，待确认 | 展示区域、映射与校验问题 | 重启恢复相同草稿，不显示为已确认 |
| 映射过期 | 指出大纲/细化已变化，禁止生成 | 按稳定 ID 保留可用配置，由用户重新确认 |
| 等待审批 | 显示完整套版预览及具体版本 | 审批中心派生同一待办，点击进入本页，不能无预览快捷批准 |
| 生成失败/额度限制 | 显示真实原因及现有候选 | 不重置成未开始；用户重试，不切换收费 API |
| 进程崩溃或重启 | 显示任务中断，先核实完成证据 | 只恢复有完整产物的检查点，不能凭旧“运行中”重新提交模型任务 |
| 版本冲突 | 保留当前草稿，禁止覆盖 | 用户载入最新版本前不使用新 revision 偷偷覆盖旧编辑 |
| 渲染器/字体不可用 | 显示缺失能力及修复入口 | 不伪造预览或 QA，修复后从已完成的正文图继续 |
| 模板版 QA 通过 | 显示对应交付文件、PNG 和报告 | 点击打开/导出匹配本轮 receipt 的文件 |

模板页和图片预览需适配当前三栏布局，窄窗口按已有响应式规则纵向排列，操作区不遮住内容。表单、列表、上一步/下一步与错误均有中文可访问名称和键盘焦点反馈；长标题可换行，原始 JSON 仅放只读高级信息。

## 9. 输入保护与资源预算

只读取用户主动选择的模板。禁止全盘扫描、读取模板中指向的本地文件、访问外链或执行文件内宏、脚本及嵌入对象。模板中的文字均为待展示数据，不是工作台系统指令。

第一版导入限制：压缩文件不超过 50 MiB，解压后总量不超过 500 MiB，部件不超过 10000 个，模板幻灯片不超过 100 张，单个部件不超过 50 MiB。超限显示具体限制，不崩溃、不自动扩权。

拒绝 ZIP 路径穿越、绝对路径、重复条目、加密包、XML 外部实体/DOCTYPE、宏和需要激活的嵌入对象。外部媒体关系视为缺失资源阻止使用；普通超链接可以保留但不跟随。引用只解析包内规范路径，不能绕过工作区的真实路径与符号链接保护。

图片生成和整页渲染串行进行；不同时解码整套高分辨率 PNG。临时渲染使用独立任务目录与独立 LibreOffice profile；取消只终止本应用监管的对应进程，不退出用户正在使用的办公软件。保持原有单项目新增内存峰值不超过 4 GiB 的验收目标，实测达标前不宣称满足。

开发验收若使用 LibreOffice，必须使用工作台依赖解析所提供的 bundled headless LibreOffice，不能使用用户正在运行的桌面 LibreOffice。生产环境缺少所需渲染能力时明确阻止相应预览/QA，不添加联网渲染后备。

- Rust：`tauri_workbench.rs` 的专用命令、工作区安全导入、v3 提交验证、任务及渲染监管、SQLite 索引和恢复。
- 保留并回归原 `pptx-exporter.ts` 可编辑实现、原 QA 和 v1/v2 校验；不要把模板参数塞进原导出器改变其保证。
- 文档：本设计是本次增量范围的依据，由交互说明索引链接；完成实施后再更新实际使用说明、架构和验收状态。

### 10.2 可观察的验收条件

1. 新项目以及尚未出图的已有细化项目能上传模板，保存重开后仍显示同一文件、区域、映射、模式与确认状态；内容材料清单和分析结果没有被改写。
2. 5 页示例模板可以承载 19 页等价合成大纲，最终严格为 19 页，ID/顺序/标题不变；不会限制到 5 页或暗加 3 页。
3. 模板原型及正文区域配置可见、可改、可验证。超边界、覆盖标题栏、目录容量不足和不兼容角色均阻止确认并给出可操作提示。
4. 生成提示词包含正文区域规则与批准文字/数据，不要求模型重画 Logo；本地模板页不伪造模型调用。
5. 同一页只能批准已经保存且成功渲染的完整组合；模板、配置、规格、图片或预览哈希任一不符，批准与导出均拒绝。
6. 模板套版候选、进度、失败和审批待办跨路由/重启恢复；重复点击、延迟响应、崩溃和丢响应测试不产生重复任务或审批。
7. PPTX 保留原模板母版、版式、主题和品牌资源；标题可独立选中编辑，正文图片可移动替换，图片不拉伸、不裁切，目录没有遗留示例。
8. 真实本地渲染全部页；字体/缺字、边界、资源关系、整页比较和审批绑定检查通过。逐页目视抽查覆盖所有用到的原型、最长中文标题和目录容量边界；自动像素检查不能代替目视验证。
9. 用户原模板哈希前后相同；开发使用合成资料和独立测试数据库，不修改真实客户项目、不自动执行其审批；真实模板测试产物仅本地保留。
10. 无模板 v1/v2 的材料、大纲修订、细化、视觉、导出、QA 全流程回归通过。v3 输入篡改、迁移历史修改及跨模式证据混用必须拒绝。
11. 独立打包 `.app` 的上传、保存、重启、渲染、导出、文件打开和内存实测完成后才能宣称可用。Keynote 人工打开与标题编辑单独记录；没有真实 PowerPoint 环境时明确不宣称已经验证。

### 10.3 本轮设计自检
